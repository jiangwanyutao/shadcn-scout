# 布局

顺序：确定页面类型 → 装一个现成的骨架区块 → 往里填真实内容 → 用极端内容做压力测试。不要从空白 div 开始搭。

## 1. 先确定页面在做什么

| 页面类型 | 视觉重点 | 骨架从哪来 | 常见错误 |
|---|---|---|---|
| 后台 / 高频管理 | 扫描速度、位置稳定、操作顺手 | `@shadcn/dashboard-01`、`sidebar-01~16` | 大卡片铺满屏幕，操作藏得太深 |
| 登录 / 注册 | 一个主操作，错误提示清楚 | `@shadcn/login-01~05`、`signup-01~05` | 塞进营销文案和背景特效 |
| 详情 / 设置 | 分组清楚，保存方式一致 | sidebar 区块 + card / tabs | 自动保存和手动提交混在一起，让人猜哪个生效 |
| 双栏审核 / 对照 | 左右内容能对应，状态清楚 | sidebar 区块 + resizable | 预览区、字段和错误提示互相没有关联 |
| 阅读 / 文档 | 行宽、段落节奏、能定位 | 正文 + 可收起的目录 | 套多层边框，每段都加入场动画 |
| 营销 / 落地页 | 真实内容、转化路径 | `@shadcn-studio` 区块、Ruixen；Vue 用 inspira-ui 背景加自己组合 | 每一段都用不同库的 hero 和渐变 |

找骨架的搜索词：`dashboard`、`sidebar`、`login`、`signup`、`hero`、`pricing`、`blog`、`about`、`faq`、`footer`、`navbar`。

```bash
npx shadcn@latest search @shadcn -t block -q sidebar
npx shadcn@latest search @shadcn-studio -t block -q pricing
npx shadcn-vue@latest search @shadcn -q dashboard
```

sidebar 区块之间的差别：可折叠分组、浮动、子菜单、图标折叠、双栏、右侧栏等。先 `view` 看结构再挑。装完后把区块里的菜单数据、用户信息换成项目的真实数据，把路由接到项目的 router 上。

## 2. 三个可以分开调的尺度

- **密度**：一屏能处理多少信息。后台页面不是留白越多越好；紧凑时也要保证可点击区域够大。
- **表现强度**：注意力怎么分配。默认保持低强度，只让主任务区最显眼。
- **动效强度**：见 [motion.md](motion.md)。

三者不用绑在一起，“紧凑 + 低装饰 + 轻动效”和“舒展 + 有品牌色 + 几乎不动”都成立。

## 3. 排版和间距

- 先定角色：页面标题、区域标题、正文、辅助信息、数值。角色少而明确，不要每个区块发明一种字号。
- 应用正文 14–16px；移动端输入框至少 16px（否则 iOS 会自动放大页面）。
- 需要对比的数字用 `tabular-nums`。
- 组内距离要小于组间距离：label 贴着输入框，错误信息贴着对应字段，页面标题和全局操作放在一起。
- 没有现成规范时，间距从 4 / 8 / 12 / 16 / 24 / 32 里选，按内容调整，不要所有地方都用 `p-6`。
- 容器只在需要分组、可操作或有独立状态时才加。连续的列表用间距和细分隔线就够了，不必每行套一张卡片。

## 4. 响应式

- 断点按内容实际放不下的位置来定。检查的起点是 390px、768px、1440px。
- 侧栏在窄屏变成抽屉（shadcn 的 sidebar 已经内置），要检查关闭、焦点回到原处、背景不跟着滚动。
- 表格在窄屏可以用优先列加横向滚动，或者改成列表；用户必须对比的数据不能直接隐藏。
- 触摸屏上没有 hover，藏在 hover 里的操作按钮必须能用别的方式找到。
- 底部固定的输入区要考虑软键盘和安全区（`pb-[env(safe-area-inset-bottom)]`）。

## 5. 用极端内容压力测试

| 输入 | 检查什么 |
|---|---|
| 很长的中文标题加英文编号 | 换行、截断、能不能看到全文、工具栏有没有被挤走 |
| URL、文件名、一长串没有空格的字符 | 容器能不能收缩，是否撑出整页的横向滚动（加 `min-w-0`、`break-all`） |
| 0 条、1 条、几十条、很多条数据 | 空状态、单条时的对齐、分页或虚拟滚动 |
| 0、负数、很大的数、缺失值 | 单位和对齐；缺失值不能显示成 0 |
| 多个错误同时出现 | 错误能定位到对应字段，用户输入不丢失 |

## 6. 状态

- 只在真正需要等待的区域显示加载状态，不要为了一个小请求把整页换成骨架屏。布局可预期的地方用尺寸固定的 `skeleton`，短操作直接在按钮里显示 spinner。
- 空状态要告诉用户下一步能做什么。
- 失败时保留用户输入并提供重试。Toast 不能是错误的唯一记录，需要用户处理的问题要留在对应的位置上。
- 不知道进度比例时显示阶段或不确定进度条，不要编造百分比。
